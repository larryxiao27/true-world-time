# 体积、性能与后台运行

## 0.4 当前运行状态实测

日期：2026-11-09。只读采样约 30.3 秒，未打开、关闭或切换用户窗口。测量结果描述当时状态，不是统一负载基准或长期续航检查。

| 项目 | 结果 |
|---|---|
| App 文件逻辑体积 | 883,305 字节，约 0.84 MiB |
| DMG 体积 | 491,455 字节，约 0.47 MiB |
| ZIP 体积 | 240,105 字节，约 0.23 MiB |
| 主进程 RSS 中位数 | 43.25 MiB，采样范围 42.48–43.97 MiB |
| 小组件扩展 RSS | 16.28 MiB |
| 主进程 CPU 时间增量折算 | 平均约 0.495% 的单核，采样显示最高 1.9% |
| 小组件扩展 CPU | 该采样窗口内显示为 0.0% |

RSS 可能含共享页，不能简单相加作为独占物理内存。WidgetKit 的动态绘制还涉及系统共享服务，以上没有把整个系统服务的占用算到本应用。

正常情况下每约 15 分钟进行一次网络校准；唤醒和手动校准会额外触发。时间显示不需要每秒访问互联网。

0.4 每秒诊断日志的中位长度约为 342 字节。按每秒连续记录 24 小时估算，约产生 28.2 MiB 日志；这是估算量，不是本次实际写入量。

## 0.5 的调整

- 静默启动，无 Dock 图标；再次打开 App 显示设置，关闭窗口回到后台。
- 计时和本机快照服务独立于窗口，设置窗口按需创建。
- 窗口隐藏后不再逐秒发布 UI 快照。
- 取消逐秒日志，仅记录关键事件。
- 系统改时通知与一秒轻量检测共同工作，避免以明显放慢检测为代价降低占用。
- 窗口首次打开后保留用于快速重开，因此不承诺关闭后恢复到启动时的内存水平。

0.5 已通过编译、包完整性检查和 14 项核心检查。新后台模式的内存、CPU、重新打开窗口和后台改时行为尚未在用户机器上进行同条件运行对照；不把 0.4 的采样结果宣称为 0.5 的优化结果。

## 用户验收

1. 安装后第一次打开 App，应无窗口、无 Dock 图标，组件继续显示时间。
2. 再次从「应用程序」打开，应显示设置。
3. 点关闭或「收起到后台」后，组件应继续走时；再打开应恢复设置。
4. 在后台状态调快/调回系统时间，观察真实时间及恢复延迟。
5. 实际休眠、断网检查后再比较资源占用和长期稳定性。

## 0.6 按需硬件面板

用户确认采用“设置页可见时采样，关闭后释放界面与采样器”的方案，接受少量首次使用开销。窗口从 650 加宽到 720 像素，未给组件增加监测代码。

- 每两秒读取一组固定大小的内核计数器；不启动子进程，不增加采样计时器或常驻线程。
- 隐藏、遮挡、最小化时释放采样器；关闭窗口移除全部设置视图引用。
- 没有历史样本数组；硬件型号、芯片、核心数、总内存和系统版本只缓存一次。
- App 内存面板使用 phys_footprint，和上文 0.4 的 RSS 不同口径，不能据此直接宣称优化幅度。

### 隔离采样器压力测

同一采样器进行 100 万次调用，不启动完整 App、不打开窗口、不注册登录项：

| 项目 | 结果 |
|---|---|
| 隐藏时创建 reader 数量 | 0 |
| 可见后创建 reader 数量 | 1 |
| 平均单次读取 | 约 2.29 微秒 |
| 首次初始化/热身额外物理占用 | 622,784 字节，约 0.59 MiB |
| 第 10 万次物理占用 | 2,196,352 字节 |
| 第 100 万次物理占用 | 2,196,352 字节 |
| 10 万至 100 万次增量 | 0 |

其他较短运行的首次开销约为 0.50 MiB。以上是局部采样器检查，不覆盖 SwiftUI 新界面和 ServiceManagement 框架的完整成本，也不是长期续航或整款应用零增长保证。

20 项自动化构建包括登录开关的批准/失败状态，以及隐藏时零采样和释放 reader 的生命周期。真实登录启动、界面交互与完整 App 前后内存占比仍待用户安装后验收。
